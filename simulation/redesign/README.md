# 一个独立新批名额如何分配

七种组成各有一份初筛粉体的 EIS 读数和一份旧势 MD 读数。实验室可以继续分样、补算或等待报告，但要在冻结时刻前把唯一的独立新批名额留给一个组成，也可以弃权。这里以一个七组成队列为一次重复，比较不同政策怎样使用同一批候选和资源。工时、费用、观测误差和真实状态均取自情景设定；现场参数仍待校准。

## 从一个可重放的选择读起

[事件流水](outputs/events.csv)保存了种子 874039 下从入组到独立新批的完整过程。筛选 `event=qc_released` 可以看见每份诊断何时进入决策。31.56 h 发布的分样阴性降低了对 x＝0.3 的支持；在 32 h 的 `lock` 记录中，两步政策选择 x＝0.2，独立新批的阳性结果在 47.75 h 发布。同一组候选上，单步政策提名 x＝0.4。[反向案例](outputs/counterexamples.csv)也包含单步成功、两步未成功的队列。

基准中，单步和两步的真实确认成功率分别为 85.64% 和 86.13%。两步平均少用 221.24 情景元；确认率差为 +0.49 个百分点，95% 配对区间为 −0.91 至 +1.88 个百分点。费用从初筛报告发布后起算。这些比较来自全部 1,024 个配对队列。[政策主表](outputs/policy_summary.csv) · [配对差与区间](outputs/paired_effects.csv) · [正文第 7 章源稿](results.md)

## 快速核查与完整重跑

仿真使用 Python（3.11 或以上）和 NumPy，支持 CPU 多进程。以下命令从仓库根目录运行。首次阅读可以直接核查随仓结果，包括 90 次精确回放、资源互斥、冻结截止、首批与新批的生成，以及验收结果的可见时刻。

P9.1 发布结果使用 x86-64 OpenBLAS 的 Haswell 内核。两步前瞻首先按单步效用选取有限数量的候选。若两个效用只差一个浮点末位，矩阵归约方式就可能改变入选项及随后实际观测的证据。例如，种子 874039 在 8.1983 h 的下一步曾在两个默认内核下分别表现为提交与等待。当前结果的适用条件包括这一候选排序规则。跨内核的提名稳定性仍需单独评价。

复现发布的队列与运行完整试验时，在支持 AVX2/FMA 的 x86-64 主机上使用 NumPy 的 OpenBLAS 构建。在启动 Python 前设置以下两项。Windows PowerShell 写作 `$env:OPENBLAS_CORETYPE='Haswell'` 和 `$env:OPENBLAS_NUM_THREADS='1'`；bash / zsh 命令如下。

```sh
export OPENBLAS_CORETYPE=Haswell OPENBLAS_NUM_THREADS=1
python simulation/redesign/verify.py
```

完整重跑会写回本目录的 `outputs/` 及 `parameters.csv`。可在新的检出中按顺序运行；`--workers` 是可调整的本机进程数。

```sh
python simulation/redesign/run_study.py --workers 8
python simulation/redesign/sensitivity.py --workers 8
python simulation/redesign/fit_fixture.py
python simulation/redesign/register.py
python simulation/redesign/verify.py
```

比较重跑结果时，逐次记录请使用解压后的 CSV。gzip 包头含生成时间，Windows 与其他系统也可能写入不同的 JSON 行尾。

[设计记录](outputs/design.json)给出四组种子与各阶段规模。基准 7 种政策各运行 1,024 次，5 种压力设定各运行 4 种政策、每种 256 次，共 12,288 条。独立的开发集用 192 组队列选择门槛，留出集用 512 组队列评价已冻结的选择。在 24 个联合敏感性设计点上，每个设计点用 96 组相同的种子比较 3 种政策。

### 为什么分样和独立新批给出的证据不同

每个组成有结构档 F、长期接触风险 C、局域势偏差 B 与一次初筛粉体实现 B1。F 在基准中对应 3.9、5.4、7.1 情景 mS/cm，有接触风险时扣减 1.6，以 5.0 为长期达标线。给定这一长期状态，初筛和独立新批各自制备。长期达标组成的单批实际达标率设为 0.94，长期不达标组成设为 0.10。同一粉体的两次 EIS 读数共享 B1。独立新粉体 B2 另抽一次实际表现；当它实际达标时，审核读阳的概率为 0.94，未达标时读阴的概率为 0.975。

七个组成还共享一项“当前势是否容易产生局域误差”的隐状态 G。偏差普遍率按 G 的两种状态取 0.09 或 0.64。信念由 G 的后验和条件于 G 的七张 24 状态表表示。一次 DFT 报告可通过 G 改变其他候选的判断。项目配置中 A、B 两个适配域采用交错分组，真实适用域需要由局域结构描述符标定。[待校准现场信息](../../p9/evidence/site_calibration.csv)

### 政策在冻结前如何使用信息

获得过一次同粉阳性读数，且长期达标后验 p 达到门槛 ρ 的候选，才可在冻结时提名。弃权效用为零；给定“合格提名奖励 1、错误提名损失 ρ/(1−ρ)”的权衡，提名效用为 (p−ρ)/(1−ρ)。基准 ρ 为 0.68。行动的价值取决于报告各可能结果对全队列终端效用的改善。在共享工位可用、预计能及时发布、预算有余的条件下，增益达 0.004 才追加行动。两步前瞻先评估单步前三个候选动作，另保留最佳 DFT 和适配候选，再沿每个读数分支评估可行次步。已有一项任务在制时，规划器也比较现在并行与等报告后再行动。

| 输出中的策略名 | 可在运行记录中看到的差别 |
| --- | --- |
| `screen_only` / `gate` | 前者沿用入组报告；后者按当时后验领先的三项，依次考虑分样、MD 与冲突 DFT。 |
| `myopic` / `tree` | 相同证据与预算，分别使用单步和两步条件前瞻。 |
| `tree_fit` | 独立诊断 DFT 发布阳性后可发起定向适配。补标、训练、验收及轨迹重算消耗实际排定的工位与预算。 |
| `tree_serial` / `tree_no_share` | 分别将同时在制的诊断限为一个、关闭跨候选势误差信息的传递，供消融比较。 |

工位在工序开始时计费，诊断提交时预留整项费用。质控发布后，结果才能进入后验；冻结时可撤销未开工任务，已开工任务继续占用资源。基准中没有请求适配，定向微调的实际训练收益仍需原子数据与独立验收。另有一个压力情景可触发该路径，同一已发布前缀下强制通过或拒绝，用以检验版本发布、回退及重算。[适配检查设定](outputs/fit_fixture.json) · [通过路径](outputs/fit_events.csv) · [拒绝路径](outputs/rollback_events.csv)

## 如何读政策结果

| 研究判断 | 文件与字段 | 口径 |
| --- | --- | --- |
| 抢到的名额是否有效 | [逐队列测量](outputs/replicates.csv.gz)的 `success_rate`、`wrong_nomination`、`wrong_release_rate` | 成功须长期目标达标、独立 B2 实际达标、观察窗内审核读阳；错误提名只看获提名配方的长期目标；错误放行指读阳但两个真实条件至少有一项未满足。 |
| 时间和费用是多少 | 同表的 `restricted_h`、`mean_cost` | 首个独立新批阳性到时，无阳性记 72 h；误报同样会使这个可观测时钟停止。费用包括入组后实际开始的诊断与新批。 |
| 哪些诊断有代价 | 同表的 `dft_count`、`clean_dft_count`、`false_bias_flags`、`missed_bias_count`、`true_bias_count` | 以队列为单位计数。无局域偏差时做的 DFT 仍可能排除解释。累计漏诊数除以累计真实偏差数得到漏诊比例。 |
| 适配是否发生 | 同表的 `fit_count`、`accepted_fit`、`unhelpful_fit` | 分别计请求、验收通过，以及拒绝或缺乏正向修复等真实收益代理。零请求下，条件有效率无定义。 |
| 门槛能否迁移 | [开发门槛](outputs/development.csv)、[留出评价](outputs/risk_evaluation.csv)、[配对差](outputs/risk_effects.csv)、[留出原始记录](outputs/risk_replicates.csv.gz) | 在开发队列中按错误提名比例上限 6.5% 选门槛，再评估独立队列的实际风险与确认率。 |

用[配对效应表](outputs/paired_effects.csv)比较策略时，先选择同一 `scenario`、`policy`、`reference` 与 `metric`。区间为同种子队列差值均值 ±1.96 个标准误，反映重复次数有限带来的误差；联合敏感性描述参数假设改变带来的变化。原始重复记录使用组成编号 0–6，事件记录的 `candidate` 直接使用 x＝0.0–0.6。现场检验应先估计批间差、同粉复测相关性、设备与审核节拍，再决定哪些情景范围可用于实际排程。
